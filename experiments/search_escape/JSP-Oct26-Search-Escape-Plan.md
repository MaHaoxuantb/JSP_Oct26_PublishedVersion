# JSP-Oct26-Search-Escape-Plan

©2026 ThomasB

Author: ThomasB

Prepared before the local screen. Goal: a validated original-puzzle solution.
Keep the Mini's version-5 continuation running during isolated local work.

Local mechanism screen: four cooperating threads, one trial at a time, seven
policies (control, diversity, escalation, adaptive, recombination, exact portfolio,
combined), two matched seeds, 30 seconds per trial. Start with the same archived
14-wrong-clue incumbent; no discoveries cross policies. Warmup/build excluded;
all timed trials include shape loading. This is a short mechanism screen, not a
statistical solve-speed comparison. Escalation uses explicit accelerated probe
thresholds 3/8/16 seconds; the live candidate uses 60/180/600 seconds.

Record real quality/energy, distinct published/retained/active boards, actual
repair sizes, protected work/restoration, operator CPU time/reward and total CPU.
Primary goal remains a solve; a flat short outcome does not establish equivalence.

Also test an isolated CP-SAT integer-distance and symmetric exact-cover prototype
on a complete 4×4 domain, then bounded original-puzzle neighborhoods if feasible.
Catalog preparation time must be included and restricted domains labeled. No
infeasibility claim for the full puzzle may come from a restricted shape set.

Write the measured report before promoting a full implementation. Then integrate
supported mechanisms, preserve optional alternatives behind switches, test saved
state recovery/validation and release compatibility, and use the user's explicit
authorization to restart the Mini from preserved incumbents if warranted. No fan
changes, no production binary replacement, no live SQLite transfers. All builds
and data are isolated. Keep strict worker release checks and original evidence.
